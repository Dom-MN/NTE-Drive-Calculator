# 性能指标与控制契约

本文件是 Calc、采集 Core、DLL 与性能日志的统一语义事实源，指标身份为
`calc.performance.metrics/1`。人类操作说明见[性能监控](../architecture-map.md#性能监控)。
代码接入、组件构建、组件晋升与实机验证分别判断；未完成实机验证不能标为稳定。

## 四项指标

| 显示 | 来源与算法 | 缺失与限制 |
| --- | --- | --- |
| FPS | PresentMon 的 `MsBetweenPresents`；最近 1 秒有效间隔的算术平均值换算为 `1000 / 平均毫秒` | 是游戏提交呈现的速率，不宣称为显示器实际显示帧率、GPU 完成速率或插帧后帧率 |
| 帧时间 | 与 FPS 相同来源、相同窗口的平均 `MsBetweenPresents`，单位 ms | 不是 GPU Busy、世界 Tick Delta 或 HUD 回调间隔 |
| 1% Low | 最近 30 秒同一来源有效间隔；按耗时降序取 `ceil(N × 1%)`，计算平均耗时，再取 `1000 / 平均毫秒` | 至少 1000 帧才显示；这是 slowest-frame average，不等同 P1 百分位，也不是卡顿帧占比 |
| Calc 耗时（已覆盖） | 相邻低频观测间，已覆盖游戏线程代码的去重墙钟耗时增量，除以 `KismetSystemLibrary.GetFrameCount` 的帧数增量，单位 ms/帧 | 当前覆盖为 `native_dispatch_and_hud_v1`，`cost_complete=false`；首次、帧数不增长/回退、间隔超过 3 秒时未知 |

帧数据只来自本次确认的游戏进程。多交换链按最近 1 秒有效帧最多的链选取，三个帧指标始终使用同一条链，
不能拼接游戏与视频/UI 的不同交换链。它是明确的选择策略，不保证所有游戏场景下必然选中主视口，实机需核对。
窗口按 CSV `TimeInSeconds` 划分；数据新鲜度按本机接收时钟判断，超过 3 秒不继续显示旧值。
首次、无权限、组件缺失、采集退出或样本不足显示未知；未知不是零。内存最多保留 60000 个帧样本，
超出容量时 1% Low 不显示，避免把不完整窗口冒充完整统计。界面/控制请求约每 500 ms 刷新。

## 组件耗时覆盖规则

当前入口是原生 `ProcessEventDetour` 的本方前后处理和 HUD `PostRender` 的本方后处理。
原生事件分发内执行的快照、战报观察及相关同步子调用计入其外层，不再把各服务计数相加。
使用已识别的游戏线程，原游戏回调期间暂停本方外层计时；其中触发的新本方回调独立计入。
同线程嵌套本方计时只统计最外层区间，不能重复相加。已包含统计自身在这些区间内的成本。

当前不包含独立 User 插件/宿主的全部入口、其他线程工作、Calc UI、两个 Core 的 CPU、GPU 绘制执行、
驱动及监控进程成本。因此名称保留“已覆盖”，不叫“全部开销”，也不解释为准确损失了多少 FPS。
区间平均并非逐帧峰值。不同线程的耗时不能相加后当作主线程阻塞时间。

扩大覆盖必须先登记实际入口、所属线程、外层边界与嵌套关系，再加入同一计时器，并验证关闭路径和重复调用。
跨 DLL 的快照交接保留外层累计耗时与最大步骤耗时，不能被提供方的记录结果清零；提供方返回实际扫描与核对数量。
域标识的细分耗时为 `domain_roots`、`domain_identity`、`domain_clone`，属于 `domain_keys` 等外层阶段的子项，不可重复相加。
只有全部声明范围完成入口审计与运行验证后，才能修改覆盖身份；不得仅把 `cost_complete` 改为 true。
尚未计时的入口保留在[路线图](../roadmap.md#性能监控验收)，不以估计值补齐。

## 开关与生命周期

本机 `performance.json` 保存 `overlay` 和 `linked`；首次 `overlay=false`，日志随排错开关关闭。
`linked=true` 只是“开启排错时同时记录性能”的默认偏好，本身不启动记录。

| 悬浮窗请求 | 排错开启且 linked | 采样 | 绘制 | 性能日志 |
| --- | --- | --- | --- | --- |
| 关 | 否 | 关 | 关 | 关 |
| 开 | 否 | 开 | 开 | 关 |
| 关 | 是 | 开 | 关 | 开 |
| 开 | 是 | 开 | 开 | 开 |

采样仍受已确认模式与暂停状态约束。关闭显示不取消排错联动；关闭排错不取消手动显示。
不连带开启背包、角色同步或战报。账号切换结束旧日志及旧观测，清空统计，再按本机显示偏好与新账号排错配置恢复。
退出先停止本次 PresentMon 会话，再撤销 DLL 显示请求，避免管道超时拖延采样收尾；不终止其他软件的监控会话。
采样期间每秒重新核对当前游戏进程，游戏退出、身份无法核对或进程切换时立即收尾旧采样并清空旧窗口。
采样子进程绑定非继承的 Windows Job，Calc 异常退出后由系统回收已绑定子进程。
正常停止直接通过 `ControlTraceW` 结束本次独立 ETW 会话，不额外启动停止助手。
会话名记录所属进程及创建时间；新采样启动时仅回收同一命名空间中已确认失主的会话，
权限不足或归属无法确认时保留。异常退出遗留的 ETW 会话在下次采样启动时清理。
采样进程连续十秒没有有效数据时显示具体状态，不无限显示普通等待，也不凭进程存活宣称采样正常。

Calc → 采集 Core → DLL 使用已有管道，无跨进程任意地址写入。能力为 `native_performance_v1` /
`performance.overlay.v1`，方法为 `native.performance.configure` / `performance.configure`。
参数固定为 `enabled`、`overlay` 两个布尔值，以及 `fps_milli`、`frame_us`、`low_milli` 三个可空正整数，
整数范围为 1 到 1000000000；关闭采样时不可开启显示。毫帧率表示 FPS × 1000，帧时间为微秒。
不接收任意文字、地址、脚本或游戏写入指令。旧组件无此能力时显示需要配套更新，不伪装成功。

响应区分请求状态、渲染入口安装、版本拒绝和最近实际绘制；`rendered=true` 才显示已绘制。
请求每次成功续期 5 秒，连接断开立即清理；续期停止则 DLL 的显示和计时在 5 秒到期后失效。
这里停止的是功能，不承诺卸载 DLL。正常关闭 RPC 未确认时显示未确认，不能用按钮已取消代替后端确认。

## 交付与证据

### 手动细分采样

“性能详情 → 细分采样”通过 `native.performance.trace` 控制正式签名的 Performance 插件，
对应 DLL 能力 `performance.trace.v1`、Core 能力 `native_performance_trace_v1`。
复用 UETools 的 `Performance::Record`、有界通道、窗口统计和输出线程，不另建计时器或游戏钩子。
默认只选 `hud_frame`，也可选 HUD 事件、数值事件、同步轮询、快照读取、战斗时钟、战斗观察。
所选业务未运行时没有样本，不因选择服务而启用业务；详细采样独立于四项显示和排错联动。

请求字段固定为 `action=start/status/stop`、不超过 64 字节的 `trace_id`、1–127 的服务位掩码 `services`。
同一编号的开始请求幂等，结束后不会重新启动；另一编号不能停止现有采样。
采样绑定开始时的 Core 连接；重连后不向新连接发送旧采样的状态或停止指令。
启动明确被拒绝时保留具体原因，不继续停止其他采样；启动或轮询失败后收尾也失败时，同时保留首个失败与收尾原因。
只有一个消费者，忙碌时不替换它。状态轮询续期 5 秒，断连、账号切换、模式撤权、插件维护及程序退出均停止续期并请求停止。
单次最多 120 秒或 64 MiB；停止接受后须等队列排空和文件关闭结果，未确认时不显示已保存。
丢样、写入失败或未排空均保留不完整状态。

实时服务统计与共享会话检测合并同一连接上尚未完成的 `core.status` 请求，共享该次回包并有界等待。
正常并发不视为读取失败；已完成回包不作下一次采样缓存，连接或账号代次变化后丢弃旧结果。

User 独立 DLL 的读取计时通过可选 `user.account.diagnostics.v1` 返回，显示为“账号读取”阶段。
它与采集外层的 `snapshot_diagnostics` 分开保留；内部读取、技能、觉醒和装备阶段存在嵌套，不能相加。
旧组件缺少该服务时不生成账号读取行，不把缺失值当零。

界面显示每项服务最近一组最多 600 条回调的阶段样本数、P95、P99、最大值。
缺失阶段不显示数值；原始回调、整个回调和回调间隔与本方绘制区分，嵌套阶段不能相加。
原始 `nte.performance/2` 文件由插件按自身输出契约保存，Calc 账号日志目录下保存 `calc.performance.trace/1` 的变化窗口摘要与最终状态，
账号代次改变后不接收旧结果。两者都是诊断日志，不是战报或背包事实，也不进入账号默认导出。

旧 Core/宿主/组件缺少能力时提示配套更新，不以 UETools 开发界面替代。
本功能的源代码和离线验收不替代当前正式二进制的真实游戏验收。

PresentMon 随附执行文件、固定版本清单、SHA-256、MIT 许可和来源说明；启动前核对身份。
读取兼容其 legacy v1 的 `msBetweenPresents` 与统一输出的 `MsBetweenPresents`；二者单位均为毫秒，
时间窗口只使用 `TimeInSeconds` 的数值秒，不把日期文本或其他时基强行当秒数。
没有有效样本、输出字段不匹配和权限不足分别显示原因，不把采样进程存活当作指标已可用。
字段来源见 [PresentMon v2.5.1 CSV 实现](https://github.com/GameTechDev/PresentMon/blob/v2.5.1/PresentMon/CsvOutput.cpp)。
只用自己的随机命名 ETW 会话，不自动提权、不关闭其他会话。原始 CSV 不落盘，保存的只是白名单性能统计。
日志格式及容量见[日志契约](logging-events.md#性能排错记录)。
所有离线数值样本属于测试输入，不能当作游戏性能证明。发布需验证真实 FPS、切换场景、前后台、进程重启、
悬浮窗与排错的四种组合、断连收尾及开关前后的性能变化。
