# DLL 分离与第三方信任路线图

本页记录五 DLL 分离并接入工作区后仍待完成的实机验收与后续能力。当前候选实际职责、隔离验证范围与更新规则见 [本方插件宿主](../reference/native-plugin-host.md)。本地接入完成不等于本页全部完成。

## 分离顺序与完成证据

目标 DLL 文件、必需／增强依赖、当前源码映射和阶段验收统一维护于 UETools 的 [DLL 分类与迁移](../../../UETools-NTE/docs/plugin_partition.md)。Calc 不再维护第二份内部文件清单。
面向使用者的分组和按钮影响见 [功能地图](../architecture-map.md#dll-分类与目标职责)；背包／角色同步的业务 owner 继续遵守 [同步生命周期](sync-lifecycle.md)。

Calc 侧尚需完成：

- 在真实游戏中验证 User → Combat → HUD → Performance 的启动与逆序停止、HUD 独立卸载和游戏线程资源排空，并核对未知结果保留及回退；已通过的隔离依赖／连接拒绝结果不能替代实机收尾。
- 队友原生按钮需在同一冻结候选上覆盖每行 E/Q 绑定、放 E 后的 Q 图形、技能形态、切队、菜单及反复开关，并通过逐帧耗时验收。初始化成功、离线调用次数减少和当前角色／owner 的实时读取专项互不替代；性能问题须依据细分采样定位，并在变更后的实际 DLL 上复测。
- 受保护 D3D 的防护软件兼容仍须确认。组件哈希和本方角色签名只证明来源与完整性；有活动检测或待重启处置时保持未通过，不能以更换文件哈希、构建成功或添加排除替代复核。
- 操作入口以能力及其前置条件判断就绪；某个增强插件缺失时说明受影响项目，不把整个系统都标故障。
- 按同一账号代次和任务身份管理各服务需求；停止某项业务只释放自己的需求，恢复与重试仍需明确确认。
- 保留首击冻结、正式库存完整性、未知结果不重发及账号隔离等现有行为；DLL 分类不修改历史战报或降低数据门禁。

当前工作区采用五 DLL，已完成 HUD 分离、全 DLL 保护、构建与隔离验证并接入随附包；真实游戏业务及性能验收仍待完成。旧九领域提案已由 UETools 归档，不作为数量目标；模块责任进一步分离不自动新增 DLL。

## 第三方手动信任

用户可预先不知道某个插件。拟采用本机显式信任：选择确切文件，展示来源与哈希，确认后绑定该版本；文件变化重新确认，不按目录、扩展名或文件名永久放行。
本方发布签名与用户手动信任分别记录。用户授权的第三方代码不标成“本方审核通过”，禁用授权阻止后续加载；已驻留且没有停止契约的组件需要退出游戏。

先判断加载类型与 ABI，再决定加载路径：UETools 插件、图形代理与 ASI 不能混同。缺可靠卸载契约时仅允许冷启动配置，不提供强制热卸载。
OptiScaler 是图形功能中间件，不能以白名单代替兼容验证；其官方安装说明对在线游戏另有使用警告。当前未验证它与本项目或游戏共存。
参考：[项目](https://github.com/OptiScaler/OptiScaler)、[安装说明](https://github.com/optiscaler/OptiScaler/wiki/Installation)。

此方案尚未实现；不扩大当前固定本方插件签名策略，不自动扫描或加载用户目录中的任意 DLL。
