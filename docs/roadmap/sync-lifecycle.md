# 同步生命周期与跨组件实施设计

状态：设计，尚未迁移生产实现。现状入口见 [功能与实现地图](../architecture-map.md)。本文维护 Calc 侧目标行为；DLL 资源边界由 UETools 的开发交付规范维护，Core 接口变更须在私库协议中定义后再由 Calc 消费。

## 立即刷新与重启同步

保留两个独立语义。当前按钮“重启同步”的停止再重建含义合理，不把它悄悄替换为一次读取。先完善现有重启的范围与收尾保证；再增加普通使用的“立即刷新”。新增入口未实现前，功能文档不能将其写成现有按钮。

| 操作 | 用途 | 会话与监听 | 失败处理 |
| --- | --- | --- | --- |
| 立即刷新 | 希望尽快取得一次最新数据 | 在有效会话内请求新读取；保留监听和其他消费者 | 保留旧快照，明确等待／失败；连接已坏时引导重启，不暗中扩大操作范围 |
| 重启同步 | 同步会话异常、停滞或需要重新建立 | 停止旧同步会话及其子任务，收尾完成后重建该会话 | 收尾未完成则不启动第二套；共享资源无法独立恢复时明确等待或说明受影响功能 |

重启同步不等于重启游戏、卸载 DLL，也不保证必须结束采集 Core 进程。只有连接不可恢复且相关消费者已经协调收尾时，才可按进程 owner 的规则重建 Core。旧账号已保存数据不因两种操作而删除。

## 接口、会话与能力所有权

最上层是面向用户操作的业务接口；接口交给会话服务编排，会话持有子任务，模块和 DLL 实现具体能力。接口层不直接逐个拆除 Hook。

| 层次 | 目标 owner | 责任 |
| --- | --- | --- |
| 用户操作和账号提交 | Calc | 模式授权、账号代次、发起请求、最终保存和显示 |
| 同步会话与子任务 | 采集 Core | 自动同步需求、手动刷新、角色／背包子任务、合并和安全重试 |
| 游戏内观察和读取 | DLL 能力 owner | 游戏线程执行、读取预算、来源修订、订阅和回调排空 |
| 配装分配和战报分析 | 计算／分析 Core | 独立冻结任务，与采集生命周期分离 |

当前部分同步状态机仍位于 Calc。迁移时以一个明确操作为单位转移所有权，并删除旧编排入口；不能让 Calc 和采集 Core 各保留一套互相竞争的同步状态机。模式权限和账号持久化继续属于 Calc。

## 停止范围

关闭自动同步仅撤销自动会话持有的角色／背包任务和订阅。手动角色任务、战报、HUD 等独立消费者不随之停止。关闭整个同步会话时，结束该会话拥有的所有子任务；是否属于该会话必须由代码中的 owner 明确表达。

停止完成的含义：不再接受该会话的新需求；取消或排空已有任务；撤销该会话订阅；迟到结果不能提交。只写 enabled=false 不能证明上述收尾完成。

共享能力最后一个消费者释放后，DLL 才收尾对应底层工作。DLL 的真实卸载另受在途调用、回调和驻留策略约束。Core 断连时 DLL 必须自行回收该连接需求，不依赖最后一条 stop 指令。

## 第一阶段验收

| 情景 | 应观察到的结果 | 所需证据 |
| --- | --- | --- |
| 正常重启 | 旧会话收尾后才出现新会话；旧快照保留 | 生命周期事件与专项行为验证 |
| 重复点击／取消重启 | 无重复会话，无取消后重新启动 | 请求身份、终态和专项验证 |
| 普通刷新 | 读取任务更新，已有监听身份不变 | 待实现后的接口验证与实机记录 |
| 读取期间来源变化 | 本次不完整候选不发布；等待或重读有明确状态 | 带来源修订的回归样本 |
| 切换账号／模式撤权 | 旧任务和迟到结果不能写入新账号 | 账号代次、取消与持久化验证 |
| 战报与同步共享能力 | 停止一个消费者不错误撤销另一个；未支持并行时明确拒绝 | 依赖／订阅契约与对应实机验证 |
| Core 断开／DLL 读取超时 | 有界收尾，区分通信错误与游戏内无进度 | 实际组件哈希、阶段、错误码与时间记录 |

实机证据保留游戏构建、实际组件身份、协议／schema、样本版本、步骤和预期依据。离线样本通过不代表游戏线程、Hook 和性能已验收。本地故障材料可保留绝对路径，但不进入默认源码或发行包。

## 实施顺序

先固定当前组件组合和证据，再完善现有重启的 owner／终态约束；随后实现保留会话的刷新请求。根据真实复用关系明确读取与观察能力，再迁移同步编排并拆分 DLL。每一步更新实际调用方、所属项目的协议及有针对性的验证；不一次性重写三个项目。

正式交付前再核对上游变化。源码合并、编译、组件晋升、安装部署与实机验收分别记录，不能互相替代。
